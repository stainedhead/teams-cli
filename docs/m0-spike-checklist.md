# M0 spike checklist (real tenant)

These spikes need a sandbox Microsoft 365 tenant, a Teams-licensed test agent user and the shared Entra app. They cannot run in this repository's CI (BLD-4) or on a developer machine without those, and they are outside this build. The output of M0 is a spike report that confirms or refutes each item in `unverified-assumptions.md`. Spike S-10 belongs to M0/M5.

Exit criteria (PRD s13): measured poll latency, throttling behaviour and re-enrollment interval recorded.

Safety rules for every spike: use only the sandbox tenant and the test agent user; post only to chats and channels created for the test; never reuse production chats or tokens; record request ids but never tokens or message bodies in the report.

| Spike | Task | Procedure | Pass criteria | Settles |
|---|---|---|---|---|
| S-1 | Graph shape confirmation | Issue each call from the PRD command table with a delegated token: `GET /me`, chat send, channel send, channel reply (POST and GET), `GET /chats/{id}/messages` with `$top`, `$orderby` and `$filter`. Capture status, headers and one redacted JSON sample per call. Inspect a message body for HTML shapes (`<at>`, `<p>`, `<br>`, `<a>`, `<blockquote>`, `<img>`). | Each call works as the adapter assumes, or the deviation is written down. 403 body shape recorded. | UA-1, UA-2, UA-10 |
| S-2 | Device-code enrollment | A human signs in as the agent user through the device-code flow against the shared public-client app with user assignment required. Try the same flow as an unassigned user. Record which scopes need admin consent, in particular `ChannelMessage.Read.All` and `Channel.ReadBasic.All`. | Assigned user enrolls with the PRD s5 scopes; unassigned user is refused; consent behaviour recorded. | UA-4, UA-17 |
| S-3 | Non-member 403/404 | With the agent token, read and send to a chat and a channel the agent is not a member of. Remove the agent from a chat mid-session and repeat the call. Record the status, `x-ms-error-code` and `request-id`. | Non-member calls return 403 or 404 (record which); membership change is rejected on the next call. | UA-8, UA-11, UA-12 |
| S-4 | Conditional Access and refresh | Apply the proposed agent-group CA policy (named location, sign-in frequency, CAE). Let the daemon refresh non-interactively over several days; record when refresh first fails and the `reauth_required` signal. Force a 401 and observe one forced refresh. | Non-interactive refresh works; re-enrollment interval measured and recorded. | UA-13, UA-19 |
| S-5 | Send, mentions and markers | Send to a chat and a channel; send a message with a policy-built `<at>` mention and check the target is notified. Check `from.user.id` and `from.user.tenantId` on a message from an external user. Embed `<span data-teams-cli-key>` and read it back. Check retention and eDiscovery show the messages. | Scopes suffice; mention is delivered; marker survives or is documented as stripped; messages are retained and discoverable. | UA-5, UA-9, UA-18 |
| S-6 | Polling latency, throttling and delta | Measure latency from post to `inbox` visibility for 1:1, chat, @mention and channel messages at several poll intervals. Try channel `messages/delta` with a delegated token. Edit and delete messages and read `lastModifiedDateTime` and `deletedDateTime`. Send at the default rate (10 per minute, 100 per hour) and force throttling to observe `Retry-After`. | Latency, delta support, edit/delete semantics and throttling thresholds recorded; defaults stay under throttling or are adjusted. | UA-3, UA-7, UA-14, UA-21 |
| S-7 | 1:1 chat create | `POST /chats` with `chatType: oneOnOne` twice for the same pair; try with `Chat.ReadWrite` only. | Second call returns the existing chat; no extra scope is needed, or the needed scope is recorded. | UA-6, UA-16 |
| S-8 | Kill-switch drill (runbook) | Disable the Entra user, revoke sessions and disable the Okta app. Time how long until the daemon and Graph calls fail. Confirm `teams` exits 3 or 4 on the first command after failure (any 401 after refresh, `reauth_required`, revoked, or 403 on `GET /me`). Update the runbook with the measured lag. | Lag measured and recorded (target at most 60 minutes). | UA-15 |
| S-9 | Selftest dry run | Run `teams selftest` against the sandbox against the real daemon. Check the default socket path and the skill format in each target harness. | Positive and negative probes behave as in PRD s10; socket path and skill formats confirmed. | UA-19, UA-20, UA-22 |
| S-10 | Entra Agent User spike plan (PRD s11) | Provision an Agent Identity Blueprint, Agent Identity and Agent User in a sandbox (Graph beta; Microsoft 365 license; possibly the Frontier preview program). Obtain tokens through blueprint credential, agent identity token and `user_fic`. Send channel and chat messages; receive a DM and @mention by polling. Record licensing, latency, throttling and admin steps. | Report of feasibility and cost. Move to it only when provisioning is GA, license cost is acceptable, security signs off and admins accept person-like agents. | Spike plan only |

Report template for each spike: date, operator, tenant, steps taken, observed result, pass or fail, request ids, follow-up (code change, spec change or core change).

S-8 and S-9 depend on the real daemon client, which is deferred (see `deferred.md`).
